# IITM BS Degree — Machine Learning Practice (MLP) Project Guidelines & Official Rules

This document outlines the competition guidelines, evaluation criteria, deadlines, code requirements, and examination policies for the IITM BS Degree Machine Learning Practice (MLP) Project.

---

## 1. Project Overview & Problem Objective
- **Problem Statement:** Predict the rental `price_tier` (multiclass classification: tiers 1, 2, 3, 4) for commercial and shared workstations across multiple metropolitan clusters using listing features, capacity attributes, operator records, booking dynamics, customer reviews, and geographical metadata.
- **Competition Platform:** Kaggle (In-Class / Private Competition).
- **Primary Metric:** **Macro F1 Score** ($\text{Macro } F_1 = \frac{1}{4}\sum_{k=1}^4 F_{1,k}$).
  - Macro F1 treats all 4 price tiers equally, penalizing models that ignore smaller or harder classes (such as Tier 3).
- **Environment:** Kaggle CPU-only execution environment. GPU/TPU accelerators are strictly prohibited.

## 2. Evaluation Scheme & Grading Breakdown (Out of 100 Marks)

$$\text{Final Marks} = NB + M + L + S + V$$

| Component | Max Marks | Description |
| :--- | :---: | :--- |
| **NB (Notebook Quality)** | **10** | Evaluated by viva examiner based on clean structure, code modularity, documentation, pipeline design, reproducibility, and absence of data leakage. |
| **M (Milestones Completed)** | **5** | Awarded for successfully completing and submitting milestone reports via the Seek portal. Submitting at least 2 out of 5 milestones is mandatory to be eligible to complete the project. |
| **L (Leaderboard Performance)** | **30** | Scaled performance on the Kaggle public/private leaderboard:<br>$$L = 30 \times \frac{\text{Your best score} - \text{cutoff score}}{\text{Top leaderboard score} - \text{cutoff score}}$$ |
| **S (Submission Consistency)** | **5** | Activity score based on daily progression:<br>$$S = \begin{cases} 5, & \text{if public score is in top 20\% of leaderboard} \\ 0, & \text{if } N < 10 \\ 5 \times \frac{N - 10}{N_{\max} - 10}, & \text{if } N \ge 10 \end{cases}$$<br>Maximum 5 submissions allowed per day. |
| **V (Viva Voce)** | **50** | Two-stage viva examination: Level 1 (Internal Checklist & Understanding) and Level 2 (1-hour In-Depth Defense with Industry Experts). Minimum passing mark is **25 / 50**. |

## 4. Permitted and Prohibited Libraries

### Allowed Libraries:
- Core Data & Math: `NumPy`, `Pandas`, `SciPy`, `regex`, `statsmodels`
- Machine Learning & Modeling: `Scikit-learn`, `LightGBM`, `XGBoost`, `CatBoost`, `Imblearn`
- Visualization: `Matplotlib`, `Seaborn`, `Plotly`, `Wordcloud`

### Strictly Prohibited:
- Deep Learning & Neural Frameworks: `TensorFlow`, `PyTorch`, `Keras`
- NLP Packages: `NLTK`, `spaCy`, `word2vec`, `textblob`
- Pretrained Models / Pretrained Embeddings
- Automated Machine Learning: `AutoML`, `TPOT`, `AutoGluon`, `H2O`
- Serialization / Cheating via pre-saved files: `Pickle`, saving pre-fit models externally.
- External Datasets: No external datasets or web-scraped augmentation permitted.

## 5. Submission & Academic Integrity Guidelines
1. **Single Registered Notebook:** All submissions must be produced by executing the student's registered Kaggle notebook (`YourRollNo-notebook-2026t3`). Manual `.csv` uploads not generated by the notebook run will be disqualified.
2. **Collaborator Access:** The notebook must be shared with `iitmbscs2008p` with viewer access and maintained as Private throughout the term.
3. **Plagiarism Zero Tolerance:** Code is screened with automated anti-plagiarism algorithms. Any copying between students or unauthorized sources results in academic malpractice and repeating the entire project next term.
4. **Milestone Report Naming Convention:**
   - Word template converted to PDF.
   - Format: `[roll-number]_26t3_M[Milestone-Number].pdf`
   - Example: `24f2006569_26t3_M4.pdf`.

## 6. Viva Voce Preparation Roadmap

### Level 1 Viva Checklist:
- Clear understanding of the problem statement and business objective.
- Demonstration that data was loaded and preprocessed cleanly without data leakage.
- Implementation of at least 3 distinct model families.
- Well-commented, organized notebook with clear markdown headers.

### Level 2 Viva (1-Hour Industry Expert Defense):
- **Explain Your Code:** Defend mathematical decisions, why certain loss functions or encodings were selected.
- **5 Core Components:** For every model used (Logistic Regression, Decision Trees, Random Forest, LightGBM, Stacking), the student must explain:
  1. *Data Representation* (vector space, encoding, scaling requirements)
  2. *Hypothesis Class / Model Function*
  3. *Loss Function / Objective* (Multiclass Cross-Entropy / Log Loss, Gini Impurity, etc.)
  4. *Optimization Algorithm* (L-BFGS, Coordinate Descent, Greedy Recursive Splitting, Gradient Boosted Decision Trees)
  5. *Evaluation & Diagnostics* (Macro F1, confusion matrices, bias-variance trade-off).
- **Live Coding:** The student may be asked to write code from scratch or modify existing pipelines during the viva.
